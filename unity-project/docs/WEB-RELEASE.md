# Релиз через свой сайт (вместо Google Play)

Решение: игра живёт на вашем сайте, распространение напрямую, без стора.

## Почему это проще
- Не нужен аккаунт разработчика ($25), ревью, keystore для Play, правило 12 тестеров.
- Обновления = перезалил файл. Нет версий/ревью.
- Игроки — по прямой ссылке; на телефоне можно «Добавить на главный экран».

## Что выкладывать (сейчас)
**Один файл** — `prototype/index.html` (все спрайты/звук внутри, ~3 МБ, работает офлайн после загрузки).
1. Залейте файл на хостинг (любой: ваш сервер, GitHub Pages, Netlify).
2. Открывается по адресу `https://ваш-сайт/игра/index.html` или встроейте в страницу:
   ```html
   <iframe src="/игра/index.html" style="width:100%;height:100%;border:0"></iframe>
   ```
3. Прогресс игроков хранится в localStorage браузера (ключ `dm_save_v1`).

## «Обвязка» под Android (APK с сайта)
Нужен именно APK-файл для установки с сайта:
- **WebView-обёртка:** Android Studio → Empty Activity → WebView на весь экран →
  `webView.loadUrl("https://ваш-сайт/игра/")` + разрешения INTERNET →
  Sign APK (свой keystore, хранить у себя) → выложить .apk на сайт.
- Или онлайн-генераторы WebView-обёрток (webintoapp.com и аналоги).
- В APK для «полного экрана»: `android:screenOrientation="landscape"`,
  `theme` без ActionBar, WebSettings: `domStorageEnabled=true` (иначе localStorage не работает!).

## PWA (по желанию, бесплатно)
Добавить `manifest.webmanifest` (name, display: fullscreen, orientation: landscape,
icons) + строку `<link rel="manifest">` — тогда «Добавить на главный экран» даст
полноэкранный запуск без адресной строки. Сервис-воркер — если нужен офлайн.

## Монетизация на сайте (вместо AdMob)
Нативная реклама AdMob в вебе не работает. Варианты:
- **AdSense / РСЯ** (Рекламная сеть Яндекса) — блоки вокруг игрового фрейма на странице сайта.
- Прямые рекламные интеграции (брендинг фона страницы, спонсорский уровень).
- Донаты (Boosty/ЮMoney) — для фан-проекта часто лучше рекламы.
Разметка слотов в игре (`AdSlot.*`, `IAdService`) остаётся полезной: `NullAdService`
заменяется на веб-реализацию, вызывающую колбэки родительской страницы (`postMessage`).
